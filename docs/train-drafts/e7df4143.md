## What we want to improve

Detect changed Go CLI code that declares or modifies an output-format flag named --format together with field-selection flags such as --field or --field-id without adding validation to reject or canonicalize their combination. Flag cases where the formatter branch shown in the same changed files will ignore selected fields, indicating the combination silently nullifies user intent.

## Why this matters

When a chosen format (for example JSON or CSV) inherently ignores or cannot express selected fields, accepting both flags without error loses user intent and yields surprising CLI behavior. Catching diffs that introduce this pattern prompts maintainers to add mutual exclusion or input normalization so the CLI behavior is predictable.

## Examples

- Resource-listing CLI: a command adds --format=json while also accepting --field but the JSON branch serializes full objects and never references the selected fields, making --field ineffective.
- Export utility: a database export adds --format=csv together with --select-fields where CSV flattens records and cannot represent the selected nested fields, so the selector would be ignored.

## Keep it focused

- Do not flag combinable, orthogonal options such as --verbose and --color because neither renders the other inert.
- Do not flag legitimately composable options like --output=file and --compress where both flags meaningfully apply to the output result.

## Done when
